# NexaClip 设计决策与取舍

> 本文只记**非显然的取舍与"为什么不做"**，与其它三篇互补、不重复：
>
> - [`architecture.md`](./architecture.md) —— 系统架构总览（分层 / 数据模型 / API 契约 / 部署）
> - [`rag-design.md`](./rag-design.md) —— RAG 检索问答子系统的实施设计
> - [`frontend.md`](./frontend.md) —— 前端技术栈与设计决策

## AI 报告

- 只做「文本 → 大纲 → 章节 → 图文报告」主干；**砍掉**视频切片 / 关键帧筛选 / 本地向量匹配那类重依赖，改让 LLM 一次结构化输出「大纲 + 章节时间范围」，章节 start/end 直接取分块时间戳。
- 章节 seek 依赖 HTTP Range：starlette 0.37 的 `FileResponse` 不支持 Range，故手写 `core/rangeresp.py` 206 分段响应。

## 采集与去重

- **全局共享库**：一个视频一份文件/转写/报告/向量，用户归属走 `UserVid`；同视频多用户只下一次，删除按引用计数（最后一个归属消失才级联清库）。
- **本地上传** `vid = 内容 sha256 前 20 位`，天然内容去重；跳过下载直接进转写下游，覆盖 DRM/私密/失效视频。
- **失败记录不自动重试**：图集/超长这类重试只会反复撞风控；要救去采集记录页手动重试。
- **订阅过载保护靠下载并发闸 + 用户配额 + 条间限速，不靠二次截断枚举条数**——枚举窗口内新视频一轮全进采集链。

## 检索问答（RAG）

- 实施细节见 `rag-design.md`。核心取舍：起步 `sqlite-vec` 嵌入式（不引入独立向量库进程），量大再换 pgvector；三段式（向量 + BM25 → RRF → rerank）。
- **句级时间戳引用是卖点**：点引用直接跳原视频第 N 秒，比 source 级引用更强。

## 高光标注

- **核心是"标注"不是"产出 mp4"**：在时间轴标出值得回看的点，mp4 切片只是可选副产品。
- LLM 只输出分块序号 idx，start/end 由代码取真实分块时间戳（**杜绝时间幻觉**）。
- 不做：自动触发（报告完成不自动跑，用户主动点）、VLM 画面评分（纯文本够用）、自动剪辑（不主动产出 mp4）。

## 翻译配音

- 目标语言仅 zh/en（千流云 tts-flash 音色只有中英）；**源语言自动检测**（`core/langdetect.py`，零依赖），日/韩视频照样译成中/英。
- 配音**完全替换原音**（两种语言人声叠放实测互相干扰、难听；译制片标准做法即替换）。
- 每句保持自然语速、按原句 start 绝对时点 `adelay` 叠加，**不变速**（变速人声发飘）、不截断（丢词），句长溢出自然延续到下一句开口前。
- 字幕**只烧译文**（原片硬字幕抠不掉、排版归原站；ass 底部 MarginV 抬高避开）。
- 不做：声音克隆（远期）。

## 明确不做（及理由）

- **图文报告补关键帧**：边际收益窄（访谈/播客画面无信息量、教程内容转写文本已覆盖）+ 新基建成本（帧图存储 / 新端点 / `ai_chapters` 加字段 / 删视频级联清图）+ 多一次 VLM 调用多一失败面。等用户真觉得报告"太干"再评估。
- **知识图谱**：自然语言 RAG 已能回答「X 和 Y 什么关系」「哪些视频提到 X」，实体抽取 + 图存储的边际收益为零。
- **合集/Notebook 模型、思维导图/五段式纪要**：锦上添花，自然语言问答已覆盖大部分场景，列为远期。
